# Resume Career Document Editor

목적은 사용자의 기본서류를 하나의 신뢰 가능한 경력 시스템으로 관리하고, 공고별 파생본이 사실관계와 핵심 포지셔닝을 유지하면서 평가 기준에 맞게 달라지도록 만드는 것이다.

## 문서 역할을 먼저 구분하기

- **기준본:** 전체 경력과 검증된 사실을 보존하는 마스터 이력서·경력기술서다. 특정 공고에 맞추기 위해 근거를 삭제하거나 의미를 바꾸지 않는다.
- **파생본:** 기준본에서 목표 공고에 필요한 경험과 표현을 선택·재배치한 제출용 버전이다.
- **제출본:** 실제 제출한 변경 불가 기록이다. 사용자가 명시적으로 요청하지 않으면 덮어쓰지 않는다.
- **작업본:** 미확인 수치, 후보 표현과 편집 중인 구조를 포함할 수 있다. 제출 가능 상태와 구분한다.

대상 문서의 역할과 목표 공고를 확인하지 않고 편집을 시작하지 않는다. 파일명만으로 최신 기준본을 단정하지 말고 수정 시각, 저장 위치와 사용자의 설명을 함께 확인한다.

## 사실 원장을 유지하기

문서 간에 다음 항목이 일치하는지 확인한다.

- 회사명, 직책, 재직 기간과 프로젝트 기간
- 역할, 기여 범위와 의사결정 권한
- 사용자·데이터 규모, 성과 수치, 분모·기간과 측정 범위
- 제품명, 기술 용어와 출시·검증 상태
- 이직 사유, 핵심 포지셔닝과 대표 경험의 설명

충돌하면 자연스러운 표현으로 합치지 말고 출처별 값을 보여주고 확인한다. 팀 성과를 개인 성과로, 제안·PoC를 출시 결과로 승격하지 않는다.

## 채용 가독성과 정보 위계를 편집하기

채용 담당자가 짧은 시간 안에 `무슨 제품을 맡았는지 → 어떤 문제를 풀었는지 → 무엇을 판단·기여했는지 → 무엇이 달라졌는지`를 파악할 수 있게 한다. 업무 나열보다 역할의 범위, 핵심 판단과 검증된 결과를 우선한다.

공고별 파생본에서는 다음만 바꾼다.

- 상단 요약과 핵심 역량의 우선순위
- 대표 경험의 선택과 배열
- 같은 사실을 설명하는 기술·사업 관점의 밀도
- 공고 언어와 연결되는 정확한 표현

경력의 실제 의미, 수치와 책임 범위는 바꾸지 않는다. 공고 키워드를 경험에 근거 없이 삽입하지 않는다.

## 인접 스킬과 역할을 나누기

- 경험의 사실과 의미가 부족하면 필요한 부분만 `pm-experience-mentor`로 보낸다.
- 특정 자기소개서 문항의 컨셉과 후킹 서사는 `pm-drama-upgrade-mentor`가 담당한다.
- 여러 공고의 시장 시그널은 `job-posting-signal-analyzer`가 담당한다.
- 이 스킬은 확보된 경력 사실을 기본서류와 제출 버전에서 일관되고 읽기 좋게 관리한다.

이미 다른 스킬에서 확인된 사실을 다시 인터뷰하지 않는다.

## 변경을 보여주고 버전을 남기기

사용자가 문서 수정을 요청하면 가능할 때 다음을 제공한다.

1. 변경 전후 비교
2. 변경 이유와 연결된 공고 평가 기준
3. 사실 확인이 필요한 항목
4. 기준본 반영 여부와 파생본에만 적용할 항목
5. 제출 대상 회사·직무·날짜를 식별할 버전 정보

외부 문서는 사용자가 편집을 요청했을 때만 수정한다. 검토 요청은 진단과 제안으로 끝내고 원본을 변경하지 않는다. 개인 경력 원문, 제출본과 비공개 링크는 스킬 저장소에 복사하거나 커밋하지 않는다.
