# Mobile Capture Extractor

목적은 스마트폰 캡처 수집함에서 새 파일을 안전하게 찾아 원문과 출처를 복원하고, 사용 목적에 맞는 프로필로 구조화한 뒤 검증 가능한 기록을 남기는 것이다.

## 적용 프로필을 선택하기

사용자의 작업공간이나 요청에서 프로필이 지정되면 해당 프로필을 읽고 분류 체계, 출력 필드와 저장 위치를 따른다. 프로필이 없으면 범용 추출 결과만 만들며 임의의 도메인 분류를 발명하지 않는다.

- PM 취업준비, AI·IT·로봇·모빌리티 트렌드 아카이브에는 [pm-job 프로필](references/profiles/pm-job.md)을 읽는다.
- 다른 반복 용도는 코어를 복제하지 않고 별도 프로필로 추가한다.

## 신규 파일과 처리 이력을 구분하기

- 파일 경로, 크기, 수정 시각과 가능한 경우 콘텐츠 해시로 신규·변경·중복을 판별한다.
- 이전 처리 기록이 있고 파일이 바뀌지 않았으면 다시 추출하지 않는다.
- 신규 유입분을 오래된 백로그보다 우선할 수 있으며, 대량 백로그는 안전한 소량 배치로 나눈다.
- 같은 게시물·문서의 연속 캡처는 화면의 연속성, 작성자, 제목, 시간과 겹치는 문장을 근거로 하나의 기록으로 묶는다. 확신할 수 없으면 별도로 유지한다.

## 원문과 출처를 추출하기

- OCR 결과는 화면에 보이는 범위만 보존한다. 잘린 문장, 가려진 내용과 흐린 글자를 추정으로 완성하지 않는다.
- 앱명, 작성자, 게시 시각, 문서명과 화면에 표시된 URL을 출처 후보로 추출한다.
- 원문 링크는 화면에서 확인하거나 신뢰할 수 있게 복원한 주소만 기록한다. 찾지 못하면 찾지 못했다고 쓴다.
- 원문, 추출된 사실과 모델의 요약·해석을 구분한다.

## 원본 이미지를 보존하기

- 대상 시스템이 지원하면 원본 이미지를 레코드 본문에 첨부한다.
- 이미지 첨부 후 다시 열 수 있는지 확인한다.
- 파일을 축소·재인코딩하거나 메타데이터를 바꿀 필요가 있으면 원본과 파생본을 구분하고, 원본을 먼저 보존한다.

## 확인과 삭제를 안전하게 처리하기

다음 중 하나라도 해당하면 완료 처리하지 않고 사용자가 답할 질문을 한 문장으로 남긴다.

- 캡처가 잘려 원문의 의미가 달라질 수 있음
- 연속 캡처 일부가 누락됐을 가능성이 있음
- 출처나 원문 링크를 신뢰할 수 있게 확인하지 못함
- 프로필 분류 또는 삭제 대상 여부가 모호함
- 원본 이미지 첨부나 재열기 검증이 실패함

원본 삭제는 출력 레코드 작성, 원본 이미지 첨부와 재열기, 대상 파일 일치가 모두 검증된 파일만 후보로 삼는다. 사용자가 삭제 또는 삭제 동기화를 명시적으로 허용하지 않았으면 삭제하지 않는다. 동기화 폴더에서는 작은 표본으로 삭제 전파를 시험하기 전까지 대량 삭제하지 않는다.

## 결과를 검증하기

가능할 때 처리 결과에 다음을 남긴다.

1. 처리한 파일과 하나로 묶은 캡처 목록
2. 판독한 원문과 출처·링크의 확인 수준
3. 적용한 프로필과 분류 결과
4. 생성하거나 갱신한 레코드
5. 완료하지 못한 항목과 사용자 확인 질문
6. 삭제한 파일 또는 삭제하지 않은 이유
