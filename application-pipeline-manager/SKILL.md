# Application Pipeline Manager

목적은 지원 건수를 늘리는 것이 아니라, 지원할 가치가 있는 공고가 누락되거나 전형 중 멈추지 않게 하고 결과 데이터를 다음 합격 전략으로 연결하는 것이다.

## 지원 건을 하나의 수명주기로 관리하기

지원현황과 일정 소스를 확인할 때 각 지원 건에서 가능한 범위로 다음을 구분한다.

- 회사, 조직·직무와 공고 식별 정보
- 공고 상태와 지원 가치 판단
- 현재 전형 단계와 단계가 바뀐 날짜
- 제출 마감, 과제, 면접, 회신 기한과 후속 확인일
- 제출한 이력서·경력기술서·자기소개서·포트폴리오 버전
- 다음 행동, 담당 주체와 완료 조건
- 결과, 받은 피드백과 확인 가능한 탈락 사유

값이 없으면 추정해 채우지 않고 `미확인`, `해당 없음`, `외부 회신 대기`를 구분한다. 공고 저장, 지원 완료, 서류 검토, 면접 예정과 최종 결과를 같은 상태로 뭉개지 않는다.

## 상태와 다음 행동의 정합성을 점검하기

현재 단계만 표시돼 있고 다음 행동이나 날짜가 없으면 관리가 끝난 것으로 보지 않는다. 다음과 같은 이상 상태를 찾는다.

- 마감이 임박했지만 지원 여부가 결정되지 않은 공고
- 지원 완료인데 제출본 식별 정보가 없는 항목
- 전형 진행 중인데 다음 일정 또는 회신 확인일이 없는 항목
- 면접·과제 일정은 있으나 필요한 선행 준비가 연결되지 않은 항목
- 결과가 나왔는데 피드백과 다음 전략 반영 여부가 비어 있는 항목
- 동일 공고 또는 동일 지원 건의 중복 레코드
- 상태, 일정과 실제 대화의 최신 정보가 충돌하는 항목

외부 회신을 기다리는 상태와 사용자가 행동하지 않아 멈춘 상태를 구분한다.

## 다음 행동을 전문 작업으로 연결하기

파이프라인은 산출물을 직접 작성하지 않고 필요한 전문 팀원에게 보낸다.

- 공고 가치와 시장 적합성 분석: `job-posting-signal-analyzer`
- 지원서 컨셉과 문항 작성: `pm-drama-upgrade-mentor`
- 이력서·경력기술서 제출본: `resume-career-document-editor`
- 포트폴리오 사례와 제작 계획: `portfolio-strategy-builder`
- 면접 준비와 리허설: `interview-strategy-coach`
- 오늘 실행할 시간 배치: `career-time-manager`

각 후속 행동에는 대상 회사·직무·마감·필요 산출물과 완료 기준을 전달한다.

## 결과를 채용 전략에 환류하기

전형 결과를 단순 합격·불합격으로만 집계하지 않는다. 확인 가능한 범위에서 다음을 비교한다.

- 공고 적합도와 실제 지원 여부
- 회사·직무 유형별 서류 통과 패턴
- 제출본의 포지셔닝과 사용한 대표 경험
- 면접 단계와 반복해서 막힌 질문·주장
- 지원량 대비 준비 품질과 소요시간

표본이 적거나 탈락 이유가 공개되지 않았으면 원인을 단정하지 않는다. `확인된 사실`, `반복 패턴`, `검증할 가설`을 분리하고 다음 지원에서 무엇을 바꿀지 작은 실험으로 정의한다.

## 시간관리와 역할을 분리하기

이 스킬은 무엇이 어느 단계에 있고 다음 행동이 무엇인지 관리한다. `career-time-manager`는 개인 일정과 실제 가용시간을 보고 그 행동을 언제 수행할지 결정한다. 파이프라인의 긴 목록을 그대로 오늘의 할 일로 복사하지 않는다.

## 변경 권한과 기록 경계

사용자가 검토를 요청하면 진단과 변경 제안만 제공한다. Notion 지원현황이나 일정을 수정해 달라고 명시한 경우에만 실제 값을 변경하고, 변경 전 대상 항목과 새 상태·날짜·다음 행동을 확인한다.

공개 스킬 저장소에는 실제 회사별 지원 기록, 비공개 공고 원문, 제출본과 개인 링크를 복사하지 않는다.

## 결과 형식

가능할 때 다음을 제공한다.

1. 현재 단계별 지원 건 요약
2. 임박 마감과 멈춘 지원 건
3. 데이터 충돌·누락과 확인 질문
4. 지원 건별 다음 행동과 완료 조건
5. 전형 결과에서 확인된 패턴과 검증할 가설
6. 전문 팀원 및 시간관리로 넘길 작업
