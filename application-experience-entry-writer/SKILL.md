# 지원서 입력란용 경험 정리

같은 경험을 지원 회사의 직무에서 읽을 수 있는 문안으로 정리한다. 연구 초록을 복사하거나 자소서형 포부를 붙이기보다, 무엇을 왜 어떻게 수행했고 무엇을 확인했는지 빠르게 읽히게 만든다. 기존에 잘된 경험정리를 기준으로 필요한 부분만 바꾼다.

## 입력과 범위

회사·직무·JD, 입력란 이름과 필수 필드·글자 수·줄바꿈 허용 여부를 확인한다. 현재 대화나 기존 작업에 있으면 재질문하지 않는다. 양식을 모르면 빠진 항목만 묻고, 확인한 범위의 정리본을 먼저 제시한다. 기존 지원 전략·기업조사는 재사용하고 이 작업 때문에 전체 자소서 사이클을 다시 실행하지 않는다.

별도 입력란이 있는 서지정보와 상세 설명을 분리한다. 연구·논문은 제목, 게재지/학회, 발행기관, 게재 상태·날짜, 저자순위, ISSN 등 실제 요구 필드만 채운다. 온라인 선공개와 권호 발행, 학회 발표와 저널 게재를 구별한다. 특허는 출원과 등록, 발명자 역할을 구별한다.

## 사실 확인과 회사별 관점

- 사용자가 방금 정정한 사실을 우선하고, 연결된 Google Drive의 연구 원문·경력 자료로 역할·방법·수치를 확인한다. Google Docs 현재 경험정리, Notion 경험정리 및 이력서·경력기술서는 해당 작업의 소스 우선순위를 따른다. 이미 읽은 유효한 근거는 재사용한다.
- 회사별·시기별 토글에 같은 연구가 있어도 별도 경험으로 세지 않는다. 제목·연구 대상·기간 등으로 같은 경험을 식별한다. 이전 지원용 표현은 참고 문안이지 원문 사실보다 우선하는 근거가 아니다.
- 버전 사이 표본 수, 효과 크기, 날짜, 역할이 다르면 강한 수치만 섞지 않는다. 모집 인원과 유효 표본, 기준선과 비교군, 증감률과 퍼센트포인트를 구분한다. 해결되지 않은 차이는 제출 문안 밖의 확인사항으로 남긴다.
- JD가 업무 개선을 강조하면 요구사항·프로세스·검증 결과를, 사용자 경험을 강조하면 사용맥락·설계·평가를 앞세울 수 있다. 이는 관점 전환이며 실제 업무·산출물·권한을 추가하는 것이 아니다.
- 설문이나 인터뷰를 수행했다고 제품을 출시한 것으로, 개선안을 제안했다고 매출이나 제도 변화를 직접 만든 것으로 바꾸지 않는다. 팀 산출물과 본인 수행을 구분한다. 기술 용어는 원문과 실제 역할로 입증될 때만 사용한다.

## 문안 구성

### N+500자 초안 후 압축

최종 제한이 N자이면 먼저 내부 확장 초안을 N+500자 분량으로 작성하고, 이후 N자 이내로 줄인다. 처음부터 제한에 끼워 맞추며 방법·판단·수치를 누락하지 않는다. 확장 초안도 확인된 사실만 사용하며 분량을 채우려고 경험이나 숫자를 만들지 않는다. 근거가 부족하면 부족한 범위를 밝힌다. 제목·공백·줄바꿈은 실제 입력란의 계산 기준을 적용한다. 압축 순서는 입력란별 작성 규칙을 따르고 핵심 역할·방법·성과·인과관계를 보존한다. 확장본은 작업용이며 기본 반환·제출 문안은 검수한 N자 이내 최종본이다. 확장본 요청 시 별도 표시해 제공한다. 단어·오탈자만 고치는 요청에는 전체 재작성을 하지 않는다. 기존 writing 예산 안에서 실행한다.

먼저 입력란 유형을 구분한다. 경력 담당업무와 경험·프로젝트에는 반드시 [입력란별 작성 규칙](references/entry-writing-rules.md)을 읽고 적용한다. 학력의 통합 주요성과와 활동·수상도 해당 참조의 구분을 따른다. 아래 연구용 구조를 경력·프로젝트에 일괄 적용하지 않는다. 기존 application-form-writer의 작성 규칙을 이 참조로 이관했으며, 현재 사용자 지시와 실제 양식이 과거 사이트별 예외보다 우선한다.

연구·논문 상세 설명이 자유 서술이면 다음 구조를 기본 후보로 사용하되 양식과 분량에 맞게 합치거나 생략한다. 모든 항목을 억지로 채우지 않는다.

[직무 관련 행동과 연구 대상을 보여주는 제목]

1. 개요: 필요한 서지정보·기간·역할
2. 배경: 문제와 연구/프로젝트 목표
3. 수행내용: 실제 순서에 따라 행동·대상·방법·산출물
4. 결과: 확인한 변화·발견·지표와 측정 조건
5. 성과 또는 시사점: 발표·게재·산출물과 활용 의미를 구분

- 수행내용은 '사용맥락 분석: 관찰 자료를 분류해 요구사항 도출'처럼 짧은 기능명 뒤에 구체 행동을 적는다. 방법명만 나열하지 않고 무엇을 판단하거나 검증했는지 연결한다.
- 인터뷰 인원·시간, 평가항목 수, 프로토타입 수 등은 수행 규모로 표시하고 성과 개선 수치와 구별한다. 유의한 관계와 인과, 제안과 구현을 구별한다.
- 결과와 성과의 중복을 줄이고 실제 없는 성과는 만들지 않는다. 시사점은 연구가 제공하는 근거나 활용 범위이며 '입사 후 기여하겠습니다' 같은 자소서 결말을 기본으로 붙이지 않는다.
- 원문이 좋은 경우 제목·용어·강조 순서만 조정한다. 직무 키워드를 모두 넣기 위해 문장을 늘리지 않는다. 구체 방법과 수치를 버리고 추상적인 전문성 표현으로 바꾸지 않는다.
- 기본은 복사 가능한 한 안이다. 요청하지 않은 A/B, 별도 회사조사, 과도한 사례 탐색은 추가하지 않는다. 제한이 있으면 실제 글자 수와 공백·제목·줄바꿈 포함 기준을 확인한다.

## 반환과 검수

입력란 순서의 문안, 적용한 직무 관점, 사용한 원문 위치, 사실 확인이 필요한 차이를 간결하게 반환한다. 문안 안에 편집 메모를 섞지 않는다. 기존 값과 달라진 수치·역할은 변경 이유와 근거를 드러낸다.

필드 충족, 사실·수치·서지정보 일치, 본인 기여, 수행내용과 결과의 연결, 직무 관점, 분량을 확인한다. 멀티에이전트 실행 시 현재 writing 5분 예산과 수정 후 독립 재검수 규칙 안에서 처리한다. 이 스킬이 추가 단계나 새 에이전트를 요구하지는 않는다.

## Notion 보관과 웹 입력의 경계

이 스킬은 경험 문안 작성과 회사별 Notion 보관을 담당한다. application-form-writer는 완성 문안의 채용 사이트 입력과 임시저장을 담당한다. 채용공고 JD의 Notion 등록과 경험 문안 보관을 혼동하지 않는다.

1. 현재 요청이나 이어지는 작업에서 Notion 저장이 승인되어 있으면 다시 허락을 묻지 않고 진행한다. 문안만 요청한 경우 임의로 원본을 수정하지 않는다. 저장 위치가 불명확할 때만 대상 페이지를 확인한다.
2. 저장 직전에 대상 페이지와 기존 토글을 읽어 사용자의 직접 수정사항을 보존한다. 원본, 다른 회사 지원본, 이번 수정 대상의 경계를 확인한다.
3. 기존 페이지 구조에 맞춰 `담당업무 - 날짜 - 회사명`, `연구 - 날짜 - 회사명` 등 회사별 토글과 항목별 하위 토글로 보관한다. 날짜와 회사는 확인된 값만 쓰고, 같은 대상이 있으면 중복 생성하지 않는다.
4. 공통 원문과 다른 회사 버전은 덮어쓰지 않는다. 같은 회사 문안의 후속 수정은 대상만 갱신하되 기존 내용은 수정 전 버전으로 보존한다. 원문을 직접 수정하는 요청도 보존본을 확보한 뒤 반영한다. 페이지 전체 교체 대신 해당 항목만 변경한다.
5. 복사용 문안과 출처·글자 수·확인사항을 분리한다. 사용자가 직접 바꾼 역할·성과 수치를 이전 값으로 되돌리지 않고, 충돌하면 차이를 확인한다.
6. 저장 후 대상 토글의 제목과 본문을 재조회해 실제 문안, 끝부분 누락, 글자 수, 원문 보존을 확인한다. 도구 성공 응답만으로 검증 완료라고 하지 않는다. 결과에는 페이지 링크와 토글명, 변경 범위 및 검증 상태를 남긴다.

저장이 실패하거나 재조회가 불가능하면 작성 완료와 저장 미완료를 분리해 알리고 복사 가능한 문안을 제공한다. 결과가 불명확한 저장을 재시도하기 전에는 현재 내용을 조회해 중복을 피한다. 멀티에이전트에서는 작성자가 저장 대상과 문안을 메인에 전달하고, 메인이 저장·재조회 결과까지 확인한다. 실제 채용 사이트 입력·임시저장은 application-form-writer로 넘기며 최종 제출은 별도 요청 범위다.

## 참고 근거의 한계

연구 정리 규칙은 사용자가 좋다고 평가한 과거 회사별 결과물과 조회 로그에서 도출했으며 해당 연구 토글의 최초 작성 대화는 아직 확인되지 않았다. Notion 보관 규칙은 별도로 확인한 지원서 작성 대화의 회사별 담당업무 저장·재조회, 사용자 직접 수정 반영, 원문 덮어쓰기 후 복원 사례를 반영했다. 이 둘을 같은 작성 기록으로 취급하지 않는다. 개인 원문과 상세 감사 기록은 비공개 로컬에만 보관한다.
