# Application Prework Strategist

목적은 자기소개서와 면접 준비에 앞서 같은 공고를 제각각 해석하는 일을 막고, `직무가 해결할 문제 → 회사의 현재 우선순위 → 문항별 검증 의도 → 지원자의 증거 배치`를 하나의 기준 리포트로 확정하는 것이다. 최종 자기소개서를 대신 쓰지 않는다.

## 선행작업으로 실행하기

목표 공고의 자기소개서 문항을 쓰기 전에 이 분석을 먼저 완료한다. 같은 회사·동일한 JD 버전으로 만든 리포트가 있으면 재사용하고, 공고가 바뀌었거나 시점 의존 정보가 오래되었을 때만 갱신한다. 면접 준비는 제출 당시 리포트를 불러온 뒤 최근 이슈와 공시만 새로 확인한다.

필요 입력은 전체 JD 원문, 회사·직무명, 모든 자기소개서 문항과 글자 수다. 일부만 확보되었으면 가능한 분석부터 수행하고 누락 범위를 표시한다. 제출 마감이 임박했고 사용자가 바로 작성을 요청하면 작업을 멈추지 말고 최소한 `직무 한 줄 정의·해당 문항 의도·핵심 회사 근거·쓸 증거`를 먼저 확정한 뒤 작성 스킬로 넘긴다.

지원자 경험과 맞춤 전략을 판단할 때는 현재 대화와 연결된 경력 원문을 확인한다. 이미 확인된 경험은 다시 묻지 않는다.

## 근거를 수집하고 구분하기

직무 범위는 업로드되거나 링크로 제공된 JD 원문을 최우선 근거로 삼는다. 회사 정보는 다음 순서로 확인한다.

1. 회사 채용 페이지, 직무 소개, 공식 홈페이지
2. DART 공시, 회사 IR·실적 발표 자료
3. 대표이사·CEO 신년사, 주주서한, 공식 발표
4. 공식 뉴스룸·제품 및 기술 문서
5. 정부·규제기관·산업협회 등 1차 자료
6. 최근 이슈를 보완하는 신뢰할 만한 언론 보도

시점이 변하는 정보는 웹에서 최신 원문을 확인하고 링크를 남긴다. 현재 연도에 공개된 분기 자료는 **오늘 기준으로 실제 공개된 최신 분기까지** 사용한다. 아직 나오지 않은 미래 분기 자료를 찾거나 존재하는 것처럼 쓰지 않는다. 현재 연도 자료가 하나도 없으면 전년도 4분기 또는 연간 자료를 사용한다. 실적 대상 기간과 발표일을 구분한다.

각 핵심 내용은 다음 중 하나로 표시한다.

- **확인 사실:** 원문에서 직접 확인되며 출처가 있는 내용
- **해석:** 여러 사실을 직무 관점으로 연결한 판단
- **가설·면접 검증:** 조직 내부 정보가 없어 지원자가 면접에서 확인해야 하는 추론

수치, 시장점유율, 국가·사이트 수, 제품명, 사내 솔루션명, 기술 구조, 담당 범위를 그럴듯하게 만들지 않는다. 광고·플랫폼 회사처럼 매출액, 영업수익, 매출총이익의 의미가 다른 경우 지표를 섞지 않는다. 계산한 비율은 원자료와 산식을 함께 남긴다. 검색 결과 요약이나 AI 기업정보 페이지는 원문을 대체하지 않는다.

지원동기에 사용할 기업 성과 숫자 후보를 최소 3개 수집한 뒤 직무 관련성·최신성·정의의 명확성을 비교해 하나를 추천한다. 각 숫자에는 값과 단위, 대상 기간, 전년 대비인지 누적인지, 자료명, 발표일, 원문 링크를 붙인다. 최종 문장용 표기는 `(2026년 1분기 IR)`처럼 짧게 제시하되 출처 원장과 연결돼야 한다.

## 1. 직무 분석 리포트

JD 문장을 단순 재배열하지 말고 실제 일의 단위와 채용 논리로 바꾼다.

1. **직무 한 줄 정의:** 누구의 어떤 문제를 무엇으로 해결해 어떤 결과를 만드는 역할인지 쓴다.
2. **핵심 업무 흐름:** `업무 영역 / 실제 과업 / 입력 / 산출물 / 주요 협업자 / 기대 결과`로 정리한다.
3. **해결 문제와 존재 이유:** 산업·제품·운영의 과제와 이 역할을 별도로 채용하는 이유를 구분한다.
4. **요구 역량:** Technical·Domain·Soft로 나누고, 각각 `명시 필수 / 명시 우대 / 해석상 필요`를 구분한다. 우대사항을 필수처럼 바꾸지 않는다.
5. **원하는 인재상:** 추상 명사 대신 실제로 관찰 가능한 행동 특성으로 번역한다.
6. **JD 시그널:** 반복되는 명사보다 동사, 책임 범위, 성과 대상, 협업 구조를 우선 읽는다.
7. **지원·면접 어필 포인트:** 지원자가 증명해야 할 판단과 행동을 3~5개로 좁힌다.
8. **모호한 지점:** 공고만으로 알 수 없어 면접에서 확인할 질문을 남긴다.

## 2. 모든 문항 분석

한 문항을 쓰기 전에 전체 문항을 모아 서로 어떤 증거를 나눠 가져야 하는지 판단한다. 문항마다 다음을 작성한다.

- 원문과 글자 수, 글자 계산 기준의 불확실성
- 표면적으로 요구한 답
- 숨은 평가 의도와 그 판단 근거
- 평가 포인트 2~4개
- 반드시 보여줘야 할 증거
- 권장 주장과 전개 방향
- 맞지 않는 소재와 흔한 실패 방식
- 다른 문항과의 역할 분담 및 중복 방지
- 첫 문단이 해야 할 일
- 전체 글자 수와 문항 중요도에 따른 문단별 역할·목표 글자 수

모든 문항을 억지로 직무역량 문항으로 만들지 않는다. 성장 과정은 가치관 형성·판단 습관·성장 가능성을, 사회 이슈는 이슈 선정 기준·논리·관점의 균형을 볼 수도 있다. 회사와 직무의 언어는 평가 의도를 선명하게 할 때만 연결한다. 문항 원문에 없는 `데이터 역량`, `글로벌 역량`, `AI 전문성`을 매번 숨은 의도로 단정하지 않는다.

`이 질문에 답하지 못하면 채용자가 무엇을 의심할까?`를 먼저 정한 뒤 평가 포인트를 만든다. 평가 포인트마다 어떤 문장이나 사례가 증거가 되는지 연결하지 못하면 추상적인 분석으로 보고 다시 좁힌다.

문항 분석을 끝낼 때는 초안보다 먼저 분량 설계표를 제시한다. `문단 / 역할 / 핵심 주장·증거 / 목표 글자 수 / 중요도`를 적고 목표 글자 수 합계가 문항 제한과 맞는지 확인한다. 제목과 공백을 글자 수에 포함하는지 명시한다. 균등 배분하지 말고 평가 비중이 큰 핵심 판단·행동·성과에 가장 많은 분량을 준다. 배경은 독자가 행동의 이유를 이해하는 데 필요한 만큼만 배정한다.

## 3. 기업 분석

지원 판단과 글쓰기에 쓰일 만큼만 조사하되 다음 범위를 빠뜨리지 않는다.

- 회사의 사업 모델, 주요 고객·제품·수익 구조
- 창업부터 현재까지의 사업 변화와 중요한 전환점
- 직무와 연결된 조직·사업 영역
- 최근 3년의 주요 전략 변화와 올해 사업계획
- 당해 연도 공개 분기 IR과 전년도 4분기·연간 기준선
- 대표 메시지와 공식 전략·로드맵
- 최근 12개월의 주요 이슈, 투자, 제품·사업 변화
- 목표 직무와 관련된 AI·데이터·플랫폼 동향
- 근거가 확인되는 경쟁사와 회사의 차별점
- 회사가 풀어야 할 기회·위험과 목표 직무에 주는 의미

재무표와 SWOT를 채우는 것 자체를 목표로 삼지 않는다. 지원자의 문장이나 면접 답변에 영향을 주지 않는 숫자는 줄인다. SWOT의 기회·위협과 `활용 방안`은 사실처럼 쓰지 말고 해석 또는 가설로 표시한다. 지원자가 입사 직후 조직의 전략이나 아키텍처를 주도할 것처럼 과도한 해결책을 만들지 않는다.

AI 조사는 기술 이름의 목록이 아니라 변화와 사업 역할을 보여줘야 한다. 주요 AI 제품·기능·조직·투자·기술 제휴의 시간축을 만들고, **공식적으로 확인되는 구체적인 제품·서비스·플랫폼 이름**을 기록한다. 각 사례는 `공식 명칭 / 해결하는 문제 / 대상 사용자 / 회사 사업에서의 역할 / 연구·발표·실험·PoC·실제 출시·운영 확장 단계 / 근거 자료와 시점 / 목표 직무와의 연결`로 정리한다. 생성형 AI, LLM, Agent, RAG, 추천·개인화, Voice AI는 회사와 직무에 실제 관련된 경우에만 조사한다. 현재 강점과 한계, 향후 2~3년 방향은 공식 로드맵과 컨설턴트의 예상이 섞이지 않도록 나눈다. `AI 솔루션`, `자체 플랫폼` 같은 일반명만 있고 공식 제품명을 확인하지 못했으면 미확인으로 표시하고 문장에 창작해 넣지 않는다.

## 4. 지원 전략

분석을 실제 선택으로 바꾼다.

### 자기소개서 전략

- 이번 지원에서 반복해 보여줄 핵심 증명 주제 3~5개
- 각 주제와 사용자 경험의 매핑: `증명 가능 / 디테일 질문 필요 / 현재 근거 없음`
- 문항별 중심 주장, 사용할 사례와 새로 보여줄 인상
- 같은 경험을 재사용할 때 달라져야 할 장면·판단·정보
- 회사 고유성과 직무 전문성을 만드는 표현
- 피해야 할 범용 문구와 근거 없는 유행어
- 부족한 증거를 복원하기 위한 다음 질문
- 대표 경험별 숫자 후보와 `규모 / 제약 / 행동 / 성과` 구분

### 면접 전략

- 반드시 이해해야 할 사업 맥락과 핵심 수치
- 직무가 마주할 가능성이 높은 문제와 트레이드오프
- 예상 질문, 질문 의도, 답변에 쓸 사용자 근거
- 사실·역할·수치를 검증하는 꼬리질문
- 회사 가설을 검증할 역질문

### 현직자 질문

검색으로 확인할 수 없는 팀 내부 정보만 묻는다. 채용 배경, 팀의 현재 과제, 실제 업무별 비중, AI 기능의 기획·평가·출시 기준, 협업 구조와 PM 권한, 피드백 문화·업무 강도·성장 기회를 우선 검토한다. 질문마다 `질문 목적`과 `우선순위`를 붙인다. 현직자 프로필이 제공되면 그 사람의 실제 이력과 연결된 맞춤 질문을 별도로 만든다. 공개 자료에서 이미 답을 찾은 질문은 제외한다.

### 최종 지원 판단

리포트 마지막에 지원 추천도와 판단 근거, 지원자의 핵심 경쟁력 3가지, 지원 시 리스크, 현직자에게 반드시 확인할 사항, 지원서와 면접에서 유지할 핵심 메시지를 간결하게 정리한다. 추천도는 회사의 유명세가 아니라 직무 적합성, 증거 강도, 경력 방향, 역할의 불확실성을 함께 반영한다.

회사 정보만으로 지원자의 역량을 완성하지 않는다. 경험 근거가 없으면 `이런 경험이 있다면`으로 끝내지 말고 현재 자료에서 후보를 찾거나, 정확히 무엇을 물어봐야 하는지 질문으로 바꾼다.

## 산출물과 완료 점검

최종 리포트는 `핵심 요약 → 직무 분석 → 문항 분석 → 기업 분석 → 지원 전략 → 현직자 질문 → 최종 지원 판단 → 출처 원장 → 미확인 사항` 순으로 작성한다. 핵심 요약은 5줄 이내로 제한하고, 전체 판단을 압축하는 표 1개를 포함한다. 출처 원장에는 자료명, 링크, 출처 유형, 대상 기간, 발표일, 사용한 주장을 남긴다.

Google Docs에 축적할 때는 회사마다 최상위 탭을 정확히 하나만 사용한다. 직무 분석·문항 분석·기업 분석·지원 전략을 별도 탭으로 쪼개지 않고 해당 회사 탭 안에서 제목 단락 스타일로 구분한다. 여러 포지션을 함께 분석하더라도 동일 회사라면 한 회사 탭 안에 포지션별 제목을 둔다. 공통 작성 규칙과 프롬프트는 회사 탭이 아닌 별도 `프롬프트` 탭에 유지한다.

완료 전에 확인한다.

- JD 전체와 모든 문항을 실제로 읽었는가?
- 명시 필수·우대·해석을 구분했는가?
- 모든 문항을 같은 직무 키워드로 획일화하지 않았는가?
- 현재 공개되지 않은 분기 실적을 사용하지 않았는가?
- 지원동기에 쓸 기업 성과 숫자 후보와 자료명·기준 시점·원문 링크가 있는가?
