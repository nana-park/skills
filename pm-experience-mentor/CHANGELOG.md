# Changelog

이 파일에는 `pm-experience-mentor`의 사용자 또는 에이전트 동작에 의미가 있는 변경사항을 기록합니다.

형식은 [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)의 원칙을 간단히 따르며, 버전 번호는 [Semantic Versioning](https://semver.org/)을 사용합니다.

## [Unreleased]

### Added

- 로컬 학습자료 보관, 일반화, 검증 및 버전 업데이트 절차를 문서화했습니다.

## [0.0.4] - 2026-08-31

### Changed

- 일반 PM 용어에 실제 대상·업무·상황·본인의 판단을 연결해 누구의 경험인지 드러내도록 강화했습니다.
- 장면을 상상하기 어려우면 한 번에 하나씩 후속 질문하고 구체적인 문장을 갱신하도록 했습니다.
- 강연 사례처럼 구체적으로 설명하되, 극적 장면을 창작하거나 핵심 문제와 무관한 디테일을 늘리지 않도록 했습니다.

## [0.0.3] - 2026-08-31

### Changed

- 사용자 요청과 멘토링 자료 재검토를 바탕으로 경험 하나에 하나의 핵심 문제를 설정하고 탐색하는 규칙을 추가했습니다.
- 사용자 문제, 증상, 원인, 제약, 후속 장애물을 구분하고 발생·발견·해결 시점의 차이를 확인하도록 했습니다.
- 여러 문제를 추상적으로 묶지 않고 실질적인 공통 문제를 찾거나 독립 사례로 분리하도록 했습니다.
- 제3자가 이해할 수 있는 문제–판단–행동–결과의 연결을 검증하도록 했습니다.

## [0.0.2] - 2026-08-31

### Changed

- 멘토링 자료를 재검토하여 사실 발굴뿐 아니라 목표 역량에 맞춘 전문적 재구성, 경험 연결, 관점 전환을 핵심 행동으로 강화했습니다.
- 대화 중 더 강한 이야기 방향을 먼저 제안하고 필요한 확인 질문으로 구체화하도록 변경했습니다.
- 실제 당시 목표와 사후 제품적 해석을 구분하고, 비교본에 `[재구성 제안]` 표시를 추가했습니다.
- 원문과 개인 사례는 포함하지 않고 일반화된 패턴만 반영했습니다.

## [0.0.1] - 2026-08-26

### Added

- 대화를 통해 IT Product Manager 경험을 발굴하는 초기 스킬을 추가했습니다.
- 사용자의 직전 답변에서 다음 질문을 선택하는 적응형 멘토링 방식을 정의했습니다.
- 문제 발견 근거, 지표 논리, 우선순위, 트레이드오프, 기여도 및 피드백 루프를 탐색하는 기준을 추가했습니다.
- 솔직하고 직설적이되 사용자를 공격하지 않는 멘토링 말투를 정의했습니다.
- 원문을 보존하고 삭제, 재작성, 새로 발굴한 정보와 확인이 필요한 내용을 시각적으로 구분하는 규칙을 추가했습니다.
- 상담 녹취와 개인 경험 원문을 배포용 스킬에서 제외하는 개인정보 보호 원칙을 추가했습니다.

## 변경 기록 방법

아직 릴리스하지 않은 변경은 먼저 `[Unreleased]` 아래에 기록합니다.

- 새 기능 또는 새 동작: `Added`
- 기존 동작 변경: `Changed`
- 오류 수정: `Fixed`
- 기능 제거: `Removed`
- 개인정보 또는 안전 관련 변경: `Security`

새 버전을 릴리스할 때 `[Unreleased]`의 항목을 새 버전과 날짜 아래로 이동합니다.

```markdown
## [0.0.2] - YYYY-MM-DD

### Changed

- 새로운 멘토링 자료에서 반복 확인된 질문 패턴을 반영했습니다.
```

그다음 `SKILL.md`의 `metadata.version`, `README.md`의 현재 버전, Git 태그를 같은 버전으로 맞춥니다.
