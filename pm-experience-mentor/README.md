# PM Experience Mentor

> 현재 버전: `0.0.1`

IT Product Manager 취업을 준비하는 사용자가 자신의 경험을 대화로 복원하고, 실제 PM 판단이 드러나는 이야기로 정리하도록 돕는 Codex 스킬입니다.

이 스킬은 초안을 받자마자 완성된 문장으로 고치는 첨삭기가 아닙니다. 사용자의 답변에서 중요한 단서, 빠진 인과관계, 모호한 기여도와 숨겨진 트레이드오프를 발견하고, 한 번에 하나씩 질문하며 경험을 함께 찾아갑니다.

## 주요 기능

- 완성되지 않은 기억이나 거친 초안에서 경험 발굴
- 직전 답변을 바탕으로 다음 질문을 만드는 적응형 멘토링
- 문제 발견 근거, 우선순위, 지표, 대안, 트레이드오프 탐색
- 팀의 성과와 사용자의 직접적인 판단·기여도 구분
- PM 메인 사례와 보조 사례, 다른 직무에 가까운 사례 구분
- 원문과 변경본을 색상·취소선·라벨로 비교
- 확인되지 않은 내용을 사실처럼 창작하지 않는 근거 중심 정리

## 이런 상황에 사용하세요

- “내가 했던 프로젝트에서 PM 경험을 같이 찾아줘.”
- “경험은 있는데 무엇이 중요한지 모르겠어.”
- “내가 실제로 판단한 부분을 면접용으로 발굴하고 싶어.”
- “이 초안을 보고 한 번에 고치지 말고 질문하면서 정리해줘.”
- “원문에서 달라진 부분이 보이도록 비교본을 만들어줘.”

문장만 빠르게 매끄럽게 고치는 작업이 필요하다면 일반적인 이력서 첨삭이 더 적합합니다.

## 대화 방식

스킬은 정해진 질문지를 순서대로 읽지 않습니다. 사용자의 방금 전 답변에서 다음 질문을 선택합니다.

```text
거친 경험 설명
→ 중요한 단서 또는 모순 발견
→ 구체적인 질문 하나
→ 실제 장면·데이터·행동·판단 복원
→ 짧고 솔직한 중간 진단
→ 다음 단서 탐색
→ 충분한 근거가 모이면 경험 구조화
```

예를 들어 사용자가 다음과 같이 말할 수 있습니다.

> AI 영상통화 서비스에 자막과 아바타를 적용했어요.

스킬은 곧바로 문장을 고치기보다 다음과 같은 질문부터 합니다.

> 잠깐만요. 자막과 아바타가 솔루션인 건 알겠어요. 그런데 어떤 사용자 문제를 보고 이 기능이 필요하다고 판단했어요?

## 빠른 시작

Codex에서 다음처럼 호출합니다.

```text
Use $pm-experience-mentor to help me discover and organize a PM experience through conversation.
```

한국어로는 다음과 같이 요청할 수 있습니다.

```text
$pm-experience-mentor를 사용해서 내 PM 경험을 한 번에 첨삭하지 말고, 질문을 주고받으며 같이 발굴해줘.
```

기존 초안이 있다면 함께 제공합니다.

```text
$pm-experience-mentor를 사용해 이 원문을 기준으로 경험을 같이 발굴해줘.
충분히 정리된 뒤에는 삭제 제안은 취소선, 새로 발굴한 내용은 별도 색상으로 표시해줘.
```

## 설치

저장소를 내려받습니다.

```powershell
git clone https://github.com/nana-park/skills.git
```

Windows의 개인 Codex 스킬 폴더에 이 스킬만 복사하는 예시입니다.

```powershell
Copy-Item -Recurse -Force `
  '.\skills\pm-experience-mentor' `
  "$env:USERPROFILE\.codex\skills\pm-experience-mentor"
```

`CODEX_HOME`을 별도로 설정했다면 해당 디렉터리의 `skills/` 아래에 복사합니다. 설치 경로는 사용하는 에이전트와 환경에 따라 다를 수 있습니다.

## 시각적 비교 규칙

원문이 있을 때 다음 규칙으로 비교본을 만듭니다.

| 표시 | 의미 |
| --- | --- |
| 검은색 | 사용자가 작성한 원문 |
| 빨간색 취소선 | 삭제 또는 교체 제안 |
| 파란색 | 멘토가 재구성한 문장 |
| 보라색 | 대화에서 새로 발굴한 사실이나 판단 |
| 주황색 | 추가 확인이 필요한 사실 또는 근거 |
| 회색 코멘트 | 질문이나 변경 이유 |

색상을 지원하지 않는 채팅에서는 `~~취소선~~`, `[제안 문장]`, `[새로 발굴]`, `[확인 필요]` 라벨을 사용합니다.

## 파일 구조

```text
pm-experience-mentor/
├── README.md
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── mentor-style.md
    ├── pm-story-rubric.md
    └── visual-revision.md
```

- `README.md`: 사람이 읽는 소개, 설치 및 관리 방법
- `SKILL.md`: 에이전트가 따르는 핵심 행동 지침
- `mentor-style.md`: 질문법, 직설성, 대화 리듬
- `pm-story-rubric.md`: PM 경험 판단 기준
- `visual-revision.md`: 원문 대비 시각적 변경 규칙

## 추가 자료로 스킬 업데이트하기

새로운 멘토링 녹취, 피드백 문서 또는 경험 정리 전후 자료가 생기면 스킬을 개선할 수 있습니다. 여기서 말하는 “학습”은 모델을 재훈련하는 것이 아닙니다. 원자료를 분석해 반복되는 질문 방식과 판단 기준을 찾고, 일반화된 규칙만 `SKILL.md` 또는 `references/`에 반영하는 과정입니다.

### 1. 원자료를 로컬에 보관

민감한 자료는 이 Git 저장소 안에 두지 않는 것을 권장합니다.

Windows 예시:

```text
C:\Users\<사용자명>\Documents\pm-experience-mentor-data\
├── transcripts\
├── mentor-notes\
└── before-after-drafts\
```

macOS 또는 Linux 예시:

```text
~/Documents/pm-experience-mentor-data/
```

이 폴더에는 녹취록, 실제 이름, 회사 내부 정보, 개인 경험 원문을 보관할 수 있습니다. GitHub에는 원자료를 업로드하지 않습니다.

### 2. 업데이트 요청

Codex에 로컬 자료와 현재 스킬을 함께 제공하고 다음처럼 요청합니다.

```text
새로운 멘토링 자료를 분석해서 기존 pm-experience-mentor와 다른 반복 패턴을 찾아줘.
원자료를 저장소에 복사하지 말고, 일반화할 가치가 있는 행동 규칙만 스킬에 반영해줘.
기존 규칙과 충돌하는 부분, 성능이 좋아질 것으로 예상되는 부분, 과적합 위험을 구분해줘.
```

### 3. 변경 범위 결정

- 적용 범위가 넓고 반복적으로 관찰된 패턴만 스킬 규칙으로 추가합니다.
- 특정 멘토링 한 회에서만 나온 표현을 보편 규칙으로 만들지 않습니다.
- 기존 규칙과 충돌하면 어느 쪽이 더 많은 사례에서 유효한지 확인합니다.
- 개인 이름, 회사명, 실제 수치와 원문 문장은 일반화 과정에서 제거합니다.
- 새 자료가 기존 규칙을 바꾸지 않는다면 버전을 올리지 않아도 됩니다.

### 4. 동작 확인

업데이트 전후에 같은 가상 경험을 입력해 다음 항목을 비교합니다.

- 한 번에 완성본을 제시하지 않는가?
- 질문이 직전 답변의 단서에서 이어지는가?
- 질문 수가 과도하지 않은가?
- 본인의 판단과 팀의 실행을 구분하는가?
- 확인되지 않은 사실을 창작하지 않는가?
- 충분한 대화 후에만 시각적 비교본을 만드는가?

실제 개인정보가 포함된 자료를 테스트 결과나 스냅샷으로 커밋하지 않습니다.

## 버전 관리

현재 초기 버전은 `0.0.1`입니다.

개선 때마다 계속 `0.0.1`로 두는 것이 아니라, 동작이 달라지는 호환 가능한 개선은 마지막 숫자를 올립니다.

| 변경 | 다음 버전 예시 |
| --- | --- |
| 표현 수정처럼 동작에 영향이 없는 변경 | 버전 유지 가능 |
| 새 자료를 통해 질문 규칙·판단 기준 개선 | `0.0.1` → `0.0.2` |
| 기존 사용 방식에 영향을 주는 큰 동작 변경 | `0.0.x` → `0.1.0` |
| 안정적인 공개 인터페이스의 호환 불가능 변경 | 향후 `1.x` → `2.0.0` |

버전은 `SKILL.md`의 다음 값을 수정합니다.

```yaml
metadata:
  version: "0.0.1"
```

모노레포 전체가 아니라 이 스킬의 릴리스를 나타내도록 Git 태그는 다음 형식을 권장합니다.

```text
pm-experience-mentor-v0.0.1
pm-experience-mentor-v0.0.2
```

### 업데이트 커밋 예시

```powershell
git diff
git add pm-experience-mentor
git commit -m "Update pm-experience-mentor to v0.0.2"
git tag pm-experience-mentor-v0.0.2
git push
git push origin pm-experience-mentor-v0.0.2
```

## 개인정보 및 보안

- 녹취록과 경험 원문은 로컬 전용 자료입니다.
- 원자료를 `references/`, `assets/` 또는 README 예시로 복사하지 않습니다.
- 저장소에는 익명화만으로 충분하지 않은 실제 사례 대신 일반화된 규칙을 기록합니다.
- 커밋 전 이름, 회사 내부 정보, 로컬 절대경로와 민감한 수치를 검색합니다.
- 실수로 민감한 자료를 커밋했다면 파일 삭제만으로 끝내지 말고 Git 이력 노출 여부도 확인합니다.

## 한계

- 이 스킬은 실제 멘토 본인을 복제하거나 동일한 판단을 보장하지 않습니다.
- 자료가 많아져도 자동으로 모델이 훈련되는 것은 아닙니다.
- 입력된 경험이 불충분하면 결과보다 추가 질문이 먼저 제공될 수 있습니다.
- 최종 이력서와 면접 답변의 사실관계는 사용자가 확인해야 합니다.
